# Changelog — PR #47

## Resumo

FASE **PERFORMANCE + REDESIGN UX/UI** da addYknow: linguagem visual leve (teal suave, branco), ecrãs simplificados e carregamentos mais rápidos. Baseado no hotfix de faturas/storage Neon (PR #46) — **sem** reintroduzir filesystem Vercel e **sem** alterar lógica financeira.

## Novas funcionalidades / melhorias UX

- Design tokens teal/leve (`docs/DESIGN_TOKENS.md`)
- **Hoje** como dashboard simples: saldo hero, Entradas/Despesas/Poupança, gráfico quando há dados, últimos movimentos
- Switcher **Pessoal | Familiar** compacto com UI otimista
- **Nova despesa** enxuta (valor · descrição · categoria · conta · Anexar fatura); secundários em «Mais detalhes»
- **FAB +** com menu rápido: Despesa / Receita / Fatura
- **Falar (MEL)** minimal: «Como posso ajudar?» + sugestões discretas
- **Compras** e **Mais** reorganizados (secundário fora do dashboard)
- Nav inferior mais baixa, com ícone + label e safe areas

## Performance

| Interação | BEFORE | AFTER |
|-----------|--------|-------|
| Login → app | ~5550 ms | ~1350 ms |
| Abertura Hoje | ~4865 ms | ~743 ms |
| Hoje → Captura | ~582 ms | ~615 ms |
| Hoje → Falar | ~577 ms | ~608 ms |
| Abrir Fatura | ~583 ms | ~604 ms |
| Hoje → Compras | ~580 ms | ~607 ms |
| Hoje → Nova despesa | ~590 ms | ~621 ms |

Ganho principal: **Hoje ~6,5× mais rápido** ao remover briefing MEL + chat + insights do load e paralelizar agregações de evolução.

## O que NÃO mudou

- Storage seguro de faturas (StoredObject / Neon — PR #46)
- Isolamento Pessoal/Familiar (server-side)
- Cálculos financeiros, auth, MEL tools, schema destrutivo
- Funcionalidades existentes (movidas para Mais / Mais detalhes)
