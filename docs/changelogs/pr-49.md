# PR #49 — Landing addYknow + identidade PWA estável

## Changelog

- Redesign da landing pública: fundo `#F7FAFA`, teal `#39B8B2` / `#DDF5F3`, texto `#17252D`, navy `#173B5E` só em detalhe.
- Eliminado o hero azul escuro; estrutura logo+Entrar → hero → 3 cards demo → secção MEL → footer.
- Valores dos cards são apenas demonstração visual (nunca dados do utilizador).
- Manifest PWA: mantém `id`/`start_url`/`scope` estáveis (`/pt/dashboard`); nome `addYknow`; cores theme/background alinhadas à marca.
- Service worker `addyknow-v1` com purge de caches `mel-*` e `nina-*`.
- Metadata Next.js (`applicationName`, `apple-mobile-web-app-title`), offline.html e guia de instalação alinhados a addYknow.
- Documentação `docs/PWA.md` explica a causa do aviso «substituir app».

## New features

- Landing addYknow leve e mobile-first (sem bloco azul).
- Update PWA in-place para quem já tem a app com `id: /pt/dashboard` (Nina → addYknow).
- Toast de actualização e guia de instalação com o nome correcto da app.

## Causa da mensagem PWA

Chrome/Android identifica a WebAPK pelo `manifest.id` (+ origem). A era **Mel** usava `id: "/pt/hoje"`; **Nina → addYknow** usa `id: "/pt/dashboard"`. IDs diferentes = aplicação diferente → aviso a instalar/substituir. Esta PR **não** altera o `id` actual, para quem já tem Nina/AddYnow/addYknow receber update normal.

## Quem já tem a app instalada

| Situação | Acção |
|----------|--------|
| Ícone Nina / AddYnow / addYknow (mesmo domínio, id `/pt/dashboard`) | Abrir a app — update automático. Sem reinstalar. |
| Ícone legado «Mel» (`id: /pt/hoje`) | Remover uma vez e instalar addYknow. |
