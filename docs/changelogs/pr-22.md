## Update — causa raiz dos dados pré-preenchidos + conta `teste@nina.app`

### Causa raiz
1. **Seed histórico** — `prisma/seed.ts` → `main()` gravava a “Família Casquinha” (Salário, Continente, EDP…) na BD, outrora em `familia@nina.app`.
2. **Ciclo nos testes** — `ensure-test-users` só limpava se `inviteCode=NINA-DEMO01` / nome “Família Casquinha”. Movimentos criados por E2E/agentes em `familia@` **permaneciam** após cada deploy → pareciam “dados que voltam”.
3. **Stubs de importação** — `demoDrafts()` em `src/lib/imports/index.ts` e `DEMO_INBOX` em `src/lib/connections/email.ts` injectavam despesas fictícias ao sincronizar Ligações.
4. **Não** há seed no login (`authorize` / `registerFamily` não criam movimentos).

### Eliminação da causa
- `scripts/ensure-test-users.mjs`: esvazia **sempre** `familia@nina.app` e `teste@nina.app` em cada build.
- Import/email stubs devolvem `[]` (não inventam movimentos).
- Nova conta limpa: `teste@nina.app` / `nina123`.
- Listas: ✏️ Editar / 🗑️ Eliminar.

## Update — Nina V3 (Intelligence Engines — sem novos ecrãs)

Camada de inteligência atrás da voz/chat existente. **Sem novas páginas nem mudança de UX.**

### Engines (`src/lib/engines/`)
- **ShoppingEngine** — analisa lista, compara supermercados, recomenda onde poupa mais
- **FuelEngine** — custo real (preço + deslocação + consumo), não só €/L
- **EVEngine** — bateria, potência, tempo, preço; melhor decisão
- **SavingEngine** — ledger `NinaImpact` (diário/semanal/mensal/anual por categoria)
- **LearningEngine** — hábitos silenciosos (lojas, marcas, postos, horários)
- **RecommendationEngine** — uma opção + justificação obrigatória
- **Intelligence Layer** — escolhe o engine pela intenção («vou às compras» → Shopping, …)

### Providers
Registry em `providers.ts`; engines nunca ligam APIs directamente.

### Performance
Cache em memória com TTL nos engines (pesquisa, basket, fuel, EV).

### Voz nova (mesmos ecrãs)
- «Quanto poupei?» → Saving Engine
- «Como posso gastar menos este mês?» → Finance tip via Saving Engine
