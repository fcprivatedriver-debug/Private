# Changelog — PR 66 — build do Preview

Commit de origem do redeploy falhado: `ef2339a` no projeto Vercel **addynow**, deployment `dpl_J9jwu7p1u1k1RGxtWrpy6C1y7iWX`.

## Causa

`npm run build` corre `scripts/vercel-build.mjs` → `scripts/migrate-deploy.mjs` antes do `next build`.

1. `npx prisma db execute --stdin` não passava `--url` nem `--schema`. No Prisma 6.6+ (o lock tem 6.19.3) isso termina com `Either --url or --schema must be provided`. O script só avisava e continuava. O mesmo commit já tinha sido construído com sucesso no projeto `private-duur` em 2026-09-28, por isso este aviso não é o que faz o build sair com código 1.
2. O que faz sair com código 1 é `prisma migrate deploy` com `P1001: Can't reach database server`. As migrações usam `DIRECT_URL`. O `ensure-env` só chega a este passo se `DATABASE_URL` existir; se faltasse, o log seria `[ensure-env] DATABASE_URL is missing` e não P1001. O host em `DIRECT_URL` (ou o derivado de `DATABASE_URL_UNPOOLED` / `POSTGRES_URL_NON_POOLING` / `DATABASE_URL`) não aceitou TCP a partir do build do projeto **addynow**.

## Código

- `prisma db execute` passa `--url` com `DIRECT_URL` (nunca `--url` e `--schema` ao mesmo tempo).
- As URLs do processo de build ganham `connect_timeout=30` quando o valor está ausente ou é menor. Não altera as variáveis gravadas na Vercel.
- Se o P1001 continuar na Vercel, o log imprime só o host:porta de `DATABASE_URL` e `DIRECT_URL` e há uma segunda tentativa com DNS IPv4 (`options no-aaaa`).

## O que falta na Vercel (não é corrigível daqui)

Projeto **addynow** → Settings → Environment Variables → ambiente **Preview** (não Production):

- `DATABASE_URL` — connection string pooled do Neon (hostname com `-pooler`)
- `DIRECT_URL` — connection string direct do mesmo endpoint (hostname sem `-pooler`). Se ficar vazia, o build usa `DATABASE_URL_UNPOOLED`, depois `POSTGRES_URL_NON_POOLING`, depois `DATABASE_URL`.

Se o compute Neon estiver suspenso ou o endpoint tiver sido recriado, actualizar estas duas variáveis com as strings actuais da consola Neon e fazer Redeploy do Preview. Não apagar a base, não mudar Production, não correr `migrate reset`.

Para o teste real do Resend, no Preview que serve a app (hoje o que está no ar é `private-duur`), acrescentar também `RESEND_API_KEY` e `EMAIL_FROM`. Estas duas não participam neste erro de build.
