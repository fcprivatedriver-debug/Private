# Changelog — PR #64 (fatura automática)

## Causa do comportamento anterior

`src/lib/ocr/index.ts` era um **stub**: `recognizeReceipt()` devolvia sempre `available: false`.
Por isso o fluxo era: guardar ficheiro → «Fatura guardada» → obrigar preenchimento manual.

## Como foi implementada a análise

1. Persistir fatura (Neon `StoredObject`, path base64 intacto).
2. `analyzeInvoiceDocument` → OpenAI Chat Completions + Vision (`gpt-4o-mini` / `OPENAI_MODEL`).
3. Resposta JSON validada com Zod (`invoiceExtractionSchema`).
4. UI `InvoiceConfirmPanel`: mostra ✓/? por campo; «Confirmar e guardar».
5. `confirmInvoiceExpense` cria despesa no espaço activo + associa anexo (idempotente por URL).

## Modelo / API

- **OpenAI** SDK já usado pela MEL
- Modelo default: `gpt-4o-mini` (vision)
- Custo extra: tokens Vision por fatura (estimativa ~$0.001–0.01 / imagem)

## Campos extraídos

supplier, total (final a pagar), currency, invoiceDate, dueDate, invoiceNumber, category (slug), description, vat + confidence por campo.

## Confiança

- ≥0.75: aceite visualmente
- &lt;0.45: forçado a `null` (não inventar)
- Confirmação obrigatória antes de gravar despesa

## Categorias
